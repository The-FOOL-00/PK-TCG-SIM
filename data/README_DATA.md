# Self-play training data — schema (data/selfplay_v1/)

Generated by `tools/gen_selfplay.py` (Phase 1a). 50,000 games of v1-heuristic
self-play, `deck.csv` both sides, `PTCG_V3_EVAL` off, agent
`ptcg-heuristic-v1.0.0`. One row per **decision point** (~30 rows/game,
1,521,362 rows total across 8 shards, one shard file per worker).

Everything under `data/` is gitignored — regenerate with:

```
python tools/gen_selfplay.py --games 50000 --workers 8 --out data/selfplay_v1
```

## Shard format

Each `shard_w{worker}_{seq:03d}.npz` (numpy compressed) contains aligned arrays:

| key       | dtype   | shape    | meaning |
|-----------|---------|----------|---------|
| `x`       | float32 | [N, 170] | state features from the **acting player's** perspective (`main.encode_state`) |
| `y`       | int8    | [N]      | final game outcome for that player: **+1 win / −1 loss / 0 draw** |
| `turn`    | int16   | [N]      | turn number at the decision |
| `game_id` | int32   | [N]      | unique per game (`worker_id * 10_000_000 + game_index`); shared by both players' rows of the same game — **split train/val by this key** |

`meta.json` in the same directory holds the authoritative full 170-entry
`feature_names` list (index → name), agent version, and generation info.

## Outcome label assignment

Both seats of every self-play game are logged. When a game ends, every
decision row of the winning player gets `y=+1`, every row of the losing
player `y=−1`, and both sides get `0` on a draw. The label is therefore the
*eventual* outcome, not a per-move reward — a value model trained on
(`x`, `y>0`) learns P(win | state). Draws are rare and dropped at training
time. Because the two players' rows of one game are anti-correlated and all
rows within a game are serially correlated, any train/val split MUST group by
`game_id` (train_value.py uses `game_id % 10 == 0` → val).

## Feature index map (x, 170 dims, all scaled ≈[0, 1])

Defined by `main.encode_state` / `main.state_feature_names()` — the runtime
inference encoder and this data share that single definition (train/serve
parity). Layout:

**Board slots — indices 0–131.** 12 slots × 11 features each, order:
my active (0–10), my bench0–4 (11–65), opp active (66–76), opp bench0–4
(77–131). Empty slot = all zeros. Per-slot features (offsets within slot):

| off | name | scaling |
|-----|------|---------|
| 0 | `present` | 1.0 if a Pokémon occupies the slot |
| 1 | `hp` | current HP / 350 |
| 2 | `max_hp` | max HP / 350 |
| 3 | `damage_taken` | (max−cur) / 350 |
| 4 | `energy` | attached energy count / 5 |
| 5 | `is_ex` | 1.0 if ex (2-prize KO) |
| 6 | `is_mega_ex` | 1.0 if Mega ex (3-prize KO) |
| 7 | `best_dmg` | best attack damage / 400 (capped 800); **my** slots use the dynamic density-aware estimate (covers deck-count attacks like Hammer-lanche), opp slots the static card_data value |
| 8 | `energy_needed` | max(0, best-attack cost − attached) / 4 |
| 9 | `retreat_cost` | retreat cost / 4 |
| 10 | `weak_to_opp_active` | 1.0 if weak to the opposing active's energy type |

**Globals — indices 132–154.**
132 `turn` (min(turn,40)/20), 133/134 `my/opp_prizes_left` (/6),
135/136 `my/opp_deck` (/60), 137/138 `my/opp_hand_n` (/10),
139/140 `my/opp_discard_energy` (basic energy in discard /35),
141–143 `supporter_played`/`energy_attached`/`retreated` (this-turn flags),
144–148 my status conditions (poisoned, burned, asleep, paralyzed, confused),
149–153 opp status conditions (same order), 154 `i_am_first_player`.

**Hand composition — indices 155–169.** Count (capped 4, /4) of each distinct
card id in our deck list, in sorted-id order: ids 3, 721, 722, 723, 1145,
1158, 1205, 1227, 1235 (indices 155–163), then zero padding to 15 slots
(164–169). Deck-specific: a different deck list changes this block's meaning.

## Consumption

`training/train_value.py` (standalone, numpy-only) trains logistic regression
and a 170→128→64→1 MLP on these shards and emits `value_weights.npz` in the
inference format documented in its header. See `training/README_TRAINING.md`
for the Kaggle runbook.

# Search-distillation data — schema (data/distill_c1/)

Generated by `tools/gen_distill.py` (Phase 2c, cycle 1). Teacher-guided
self-play with the determinized-MC teacher (`tools/searcher.py`) at the
signed-off **(det=16, roll=2, topk=4)** config on BOTH seats, `deck.csv`
both sides. One row per decision the teacher actually **searched**
(MAIN-phase, single-select, >1 option — ~19 per game); pure-v1 decisions
are not logged.

```
python tools/gen_distill.py --decisions 500000 --workers 8 --out data/distill_c1
```

Known caveat (accepted for cycle 1): teacher determinizations assume the
opponent runs OUR deck list — exact in the mirror, an information leak vs
ladder conditions.

## Shard format

Each `shard_w{worker}_{seq:03d}.npz` contains, for D decisions:

| key         | dtype   | shape    | meaning |
|-------------|---------|----------|---------|
| `state`     | float32 | [D, 170] | `main.encode_state` from the acting player's perspective (same 170-dim layout as selfplay_v1 above) |
| `n_options` | int16   | [D]      | number of legal options at the decision |
| `label`     | int16   | [D]      | option index the TEACHER chose (0-based, over the full option list) |
| `turn`      | int16   | [D]      | turn number |
| `game_id`   | int32   | [D]      | unique per game, shared by both seats — **split train/val by this key** |
| `opt_x`     | float32 | [ΣnO,41] | per-option features (`main.encode_option`), concatenated in decision order; decision i's rows are `cumsum(n_options)[i-1] : cumsum(n_options)[i]` |

`meta.json` holds both feature-name maps, the exact teacher config, and the
generation caveat.

## Option feature map (opt_x, 41 dims)

Defined by `main.encode_option` / `main.option_feature_names()` (shared
train/serve definition, like the state encoder):

- **0–16** OptionType one-hot (`OT_NUMBER`=0 … `OT_SPECIAL_CONDITION`=16).
- **17–23** CardType one-hot of the referenced card (Pokémon, item, tool,
  supporter, stadium, basic energy, special energy) — for `OT_PLAY` the hand
  card, otherwise via `_option_card_id`; all zeros when no card resolves.
- **24–34** the 11-feature board-slot block (same layout as the state
  encoder's slots) of the Pokémon the option acts on: attach/evolve target,
  the active for attack/retreat, or — for benching a Pokémon from hand —
  the slot the card *would become*. All zeros when there is no board target.
- **35** `attack_dmg` — dynamic damage estimate / 400 (attacks only).
- **36** `ko_if_used` — attack would KO the opposing active.
- **37** `card_value` — heuristic keep-value of the referenced card / 400.
- **38** `targets_active` — acts on the Active Spot (or is attack/retreat).
- **39** `v1_rank` — option's rank under the plain v1 MAIN scorer / (n−1)
  (0 = v1's top choice). Computed with `_score_main` directly, so it is
  independent of any policy flag (no self-recursion at inference).
- **40** `v1_top` — 1.0 on v1's argmax option. Mean of `label`-row `v1_top`
  = the "always copy v1" floor accuracy (~53%); the student only adds value
  above it.

## Consumption

`training/train_policy.py` (standalone, numpy-only) trains a per-decision
softmax imitation model (state trunk 170→128→64, option head 105→64→1,
~37k params) with cross-entropy over each decision's options and emits
`policy_weights.npz` in the inference format documented in its header.
