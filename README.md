# PTCG AI Battle Challenge — heuristic agent (v1)

Agent for the Kaggle competition **"The Pokémon Company - PTCG AI Battle Challenge Simulation"**
(cabt Engine on kaggle-environments). Deterministic heuristic policy; no search/RL yet.

Current agent version: `ptcg-heuristic-v1.0.0` (constant `AGENT_VERSION` in `main.py`,
stamped into every eval log line).

## Setup: getting the official starter data (not in this repo)

This repo does **not** contain the competition's official data or assets —
redistributing them would violate the competition rules. The `.gitignore`
excludes them; you need to fetch them yourself:

1. Go to the competition's **Data** tab on Kaggle
   ("The Pokémon Company - PTCG AI Battle Challenge Simulation") and download
   the starter files.
2. Place them at the repo root so the layout below matches:
   - `sample_submission/` (the official sample agent, incl. `cg/`)
   - `ptcg_engine/` (engine source, incl. `cg.dll` build)
   - `Card_ID List_EN.pdf`, `Card_ID List_JP.pdf`
   - `EN_Card_Data.csv`, `JP_Card_Data.csv`
3. Install deps: `pip install -r requirements.txt` (see the Python note below
   for which `python` to use on Windows).
4. Run `python tools/build_submission.py` — this validates `deck.csv`,
   generates `card_data.json` from the official CSVs, does a smoke eval, and
   packages `submission.tar.gz`. All of these outputs are gitignored
   (`build/`, `card_data.json`, `submission.tar.gz`, `runs/`) since they're
   either derived from official data or local run logs.

## API contract (derived from starter files + kaggle-environments 1.30.1 source)

- **Entry point**: Kaggle loads `main.py` with `exec()` and uses the **last callable defined
  in the file** (`kaggle_environments/agent.py: get_last_callable`) — `agent` must stay the
  final `def` in `main.py`. It is called with `(observation, configuration)` truncated to the
  function's arity; we use `agent(obs) -> list[int]`.
- **`__file__` is NOT defined** under that exec. The agent dir is appended to `sys.path`
  during exec (and popped after), and cwd is *not* changed. `main.py` therefore resolves
  `deck.csv` / `card_data.json` at module level via `__file__` (when present) → cwd →
  `/kaggle_simulations/agent` → `sys.path` scan, with a baked-in fallback deck as last resort.
- **Deck-selection call**: `obs["select"] is None` (and `current is None`) → return the 60
  card IDs. VERIFIED: `make("cabt", configuration={"decks": ...})` is stored but **ignored**
  by the interpreter — agents returning `[]` on the first call lose immediately with
  "deck does not have 60 cards". Decks come only from each agent's first answer.
- **Decision call**: return option **indices** into `obs["select"]["option"]`, length within
  `[minCount, maxCount]`, each `0 <= i < len(option)`, no duplicates. `minCount` can be 0.
  Many selections need multiple indices. Illegal answer or exception = status INVALID =
  **instant loss** (cabt.py interpreter).
- **Observation**: `select` (type/context enums, options with structured fields like
  `attackId`, `area`, `index`, `cardId`), `logs`, `current` (turn, yourIndex, players[2]
  with active/bench/hand/prize/deckCount, flags), `remainingOverageTime` (600 s per player
  for the whole game; `actTimeout=0`). Enum values are copied from the sample's `cg/api.py`
  into `main.py` constants.
- Rewards: win 1 / loss -1 / draw 0. Built-in baseline agents: `"random"`, `"first"`.

## Deck

`deck.csv` = the official sample submission's deck, unchanged: Kyogre ×2, Snover ×4,
Mega Abomasnow ex ×4, Mega Signal ×4, Cyrano ×2, Lillie's Determination ×4, Waitress ×4,
Maximum Belt ×1, Basic Water Energy ×35. Chosen because it is the simplest plan available:
one evolution step, a single attacker line, heavy basic energy. Validated by
`validate_deck()` (60 cards, IDs exist in the engine DB, 4-copy rule by card name with
basic energy exempt, ≤1 ACE SPEC, ≥1 Basic Pokémon).

Known dynamic: only **6 Basic Pokémon** in 60 cards, so games often end by
"No Pokémon in Active Spot" (result reason 3) when a thin board is wiped, not by prizes.
This is symmetric in self-play but is the main deck-level tuning lever for later.

## Agent design (main.py)

One scoring function over the legal options; one resolution path for every phase:
`resolve_selection(options, scores, min_count, max_count)` picks positive-scoring options
(best first) up to `maxCount`, then pads with least-bad options to `minCount`; ties break
on lowest index → fully deterministic, zero randomness.

Weight ordering encodes turn structure — **attacking ends the turn**, so every setup action
scores above attacks: energy attach (3000) > evolve (2800) > item (2400) > bench (2300) >
supporter (2150, after bench/items so hand-shuffle draws cost less) > tool/ability/stadium >
attack (1000 + damage/2, capped below setup) > retreat (-500) > end (-1e6).
Lethal attacks (est. damage ≥ opponent active's current HP) score 100000.
Damage estimates use `card_data.json`; Riptide is computed from basic energy in our discard,
Hammer-lanche from remaining deck energy density; weakness ×2 and Maximum Belt +50 are
applied when the defender's card is in our data (mirror matches).
Context-specific choices: setup active = highest HP basic; promote = HP + attached energy +
attack strength; discards prefer basic energy (35 copies) and protect Pokémon; damage
targets prefer lowest HP; mulligan redraws only when the hand has no Basic; go first = Yes.

Crash-proofing (verified by the build's import check): top-level try/except; every return
passes `_validate_result` (range/duplicate/count enforcement); any failure returns `[0]`
(or first `minCount` indices) and logs turn + compact option dump to stderr; missing
`deck.csv`/`card_data.json` degrade gracefully (baked-in deck / empty card data).

## Results (2026-07-07, 30 games per series, kaggle-environments 1.30.1, local)

| series      | W/L/D   | crashes | fallbacks | avg turns | avg ms | p99 ms | max ms |
|-------------|---------|---------|-----------|-----------|--------|--------|--------|
| vs self     | 23/7/0¹ | 0       | 0         | 6.4       | 0.033  | 0.107  | 0.652  |
| vs random   | 27/3/0  | 0       | 0         | 7.4       | 0.036  | 0.121  | 0.204  |

¹ self-play "wins" = seat 0's result: both seats are this agent, so 23/30 measures
first-mover advantage, not strength. vs random alternates seats (14W/1L as P0, 13W/2L as P1).

Time budget: ~35 decisions/game × <0.1 ms avg ≈ **milliseconds of agent time per game**
against the 600 s allowance; max single decision 0.65 ms (cap target <1 s).

## Assumptions / UNCONFIRMED

- Kaggle image kaggle-environments version (see V2 above).

- The official "differences from real PTCG rules" document is not in the starter files;
  simulator behavior inferred from the C++ source and observed games only.

- `env.render(mode="html")` is empty for cabt in the pip package (no visualizer shipped);
  we save `env.toJSON()` replays instead.
